# Проєкти та відновлення через CLI

Формат v1 зберігає копії зображень, робочі captions, історію текстів, параметри й checkpoints. Базовий [GUI](GUI.md) уже доступний; персоналізовані `TRAINING_ADVICE.txt` ще не реалізовані. Команди нижче запускаються з кореня репозиторію; на Windows замініть `.command` на `.bat` і задайте потрібний профіль.

## Звичайний цикл

```bash
./captioning_tool/auto_captioning_tool.command --input /path/to/images --output projects/my-dataset
./captioning_tool/auto_captioning_tool.command --resume projects/my-dataset
```

Ctrl+C зупиняє виконання зі збереженням завершених стадій. Resume використовує збережені промпти й параметри; явно передані аргументи перевизначають їх. У `.command` defaults Mac застосовуються лише до нового проєкту. Незавершена стадія повторюється; завершені актуальні стадії пропускаються. Якщо роботи немає, моделі та GPU не завантажуються. Launcher усе одно перевіряє своє Python-середовище.

Відкрийте `review.html` для перегляду, редагуйте TXT у `captions/`. Зміни розпізнаються під час наступного resume, попередні тексти залишаються в `caption_history/`. Редагування скидає затвердження. Після власного перегляду затвердьте всі завершені captions і створіть експорт:

```bash
./captioning_tool/auto_captioning_tool.command --resume projects/my-dataset --export-only --approve-all
```

`--approve-all` — явна дія користувача, а не оцінка якості моделлю. У CLI це масове затвердження; GUI також підтримує вибіркове. `--export-only` не запускає inference. Незатверджені та незавершені captions не експортуються.

## Політики TXT

- `fill-missing` (default): заповнює відсутні/незавершені captions і оновлює застарілі незатверджені модельні тексти. Імпортовані, вручну відредаговані й затверджені завершені captions захищені.
- `preserve`: не генерує captions взагалі, навіть якщо текст відсутній; стадії регіонів можуть виконуватися.
- `regenerate`: перегенеровує лише явно вибрані зразки, зберігаючи попередній текст в історії та скидаючи затвердження.

```bash
./captioning_tool/auto_captioning_tool.command --resume projects/my-dataset --caption-policy regenerate --select original-photo.jpg
./captioning_tool/auto_captioning_tool.command --resume projects/my-dataset --check
```

`--select` приймає sample ID, внутрішнє ім’я зображення або вихідний відносний шлях, включно з підпапкою. `--check` показує IDs, статуси й чергу без запису або перевірки GPU. Зміна caption prompt впливає тільки на відповідні незахищені captions; зміна region prompt — на grounding і SAM. Відсутня/змінена маска повторює SAM, якщо grounding актуальний.

## Імпорт і перенесення

Сусідні непорожні UTF-8 `.txt` імпортуються без зміни байтів. Неоднозначний TXT для двох зображень з однаковим stem відхиляється. Для імпорту без моделей:

```bash
./captioning_tool/auto_captioning_tool.command --input /path/to/image-txt-pairs --output projects/imported --import-only
```

Старі outputs без `project.json` не можна відновлювати напряму: імпортуйте їхню папку `dataset/data/` або `onetrainer/data/` у новий проєкт. Прийняті 40 COCO captions уже імпортовані в `projects/coco40-resumable` і затверджені відповідно до попереднього приймання користувачем.

Переносьте всю папку проєкту та запускайте `--resume` за новим шляхом. Після завершеного імпорту вихідна папка не потрібна. Для незавершеного копіювання або додавання файлів задайте `--input` з початковою структурою; зміна байтів уже відомого оригіналу відхиляється. IDs не змінюються при додаванні файлів. Кеш моделей задається окремо через `--models`; Python runtime слід відтворити для цільової платформи.

## Зберігання та snapshots

`project.json` містить `schema_version: 1`, UUID проєкту, джерела зі стабільними source/sample IDs, SHA-256, відносні шляхи, параметри, промпти й `latest_export`. Записи зразків у `regions/` містять окремі статуси виконання та перевірки. Редагуйте робочі TXT; ручне редагування JSON не є підтримуваним інтерфейсом.

Записи замінюються атомарно; блокування ОС не дозволяє двом CLI одночасно записувати проєкт. Історія captions зберігається за хешами. Незавершений запис модельного TXT не визнається ручною правкою або завершеним caption після аварії. Це перевірка відновлення після переривань процесу, не гарантія проти пошкодження диска чи втрати живлення.

`exports/<id>/` містить незалежні image/TXT пари, `dataset_manifest.json` та контрольні суми у `snapshot.json`. `--no-training-config` обирає `dataset/data/`, інакше додається OneTrainer-пакет. Snapshot готується в `.partial-*` і публікується перейменуванням після завершення. Часткові каталоги ігноруються; попередні завершені експорти залишаються. Без змін повторний експорт повертає той самий валідний snapshot. Після зміни затвердженого складу створюється новий; якщо затверджених captions немає, `latest_export` стає `null`.

Після переміщення проєкту повторний `--export-only` створює OneTrainer snapshot з новими абсолютними шляхами. Незалежний dataset-only snapshot може використовуватися повторно. Старі snapshots не редагуйте; локальний шлях базової моделі за потреби змініть через `--base-model`.

## Перевірено на поточному Mac

- 31 автоматичний тест: аварії запису/імпорту/експорту, історія правок, стабільність IDs, fingerprints, блокування, пошкоджені артефакти, відновлення та повторний експорт.
- Реальний Compact/MPS запуск на двох фото: SIGINT після першого caption, код 130; після переміщення проєкту й недоступності вихідної папки завершено лише другий. SHA-256 і час зміни першого TXT лишилися незмінними.
- Повторний запуск: 2 завершені captions, 0 помилок, 0 запланованих стадій, без inference.
- Імпорт прийнятих 40 COCO captions: 40 експортованих пар без генерації; повторний export-only використав той самий snapshot.

Візуальні та семантичні порівняння не виконувалися відповідно до побажання користувача. GUI Stop/Resume перевірено через headless Qt з реальним MPS worker; Windows resume, навчання та masked export ще не перевірені.
